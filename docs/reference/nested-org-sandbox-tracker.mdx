Full nested organization sandbox mode is not implemented.
The first runtime slice adds optional org identity to existing exec/SSH/TCP relay control paths, but it does not create nested per-org boundaries.
The relay attribution slice records that org identity on relay OCSF events when present.
This tracker lists the remaining changes before multiple customer organizations can safely share one outer container.
Rows marked `done` are local spike evidence only unless they link to CI artifacts.

## Tracker

| Status | Work | Acceptance |
|---|---|---|
| done | UID/GID binary policy | Same binary can be allowed for one agent UID/GID and denied for another inside one org sandbox. |
| done | Supervisor-managed exec user | `openshell sandbox exec --user <name>` runs a command as a non-root sandbox OS user. |
| done | Local pooled-container smoke | Local spike showed separate org containers in one Docker host can be isolated by separate networks; shared networks leak reachability. |
| done | Real OpenShell sibling marker smoke | Local spike showed two gateway-managed sandboxes did not expose Org B's in-sandbox marker through Org B's Docker container IP. This is one negative reachability check, not general sibling isolation. |
| done | Org identity API/relay foundation | Optional `org_id` is validated on exec/SSH/TCP forward requests, propagated to `RelayOpen`, persisted on SSH sessions, returned in create-session responses, and enforced on SSH forward-token validation. Empty `org_id` preserves legacy sandbox-level behavior. |
| done | Relay OCSF org attribution | Relay open/closed/failed events clone the base sandbox context with `RelayOpen.org_id` and emit it as `unmapped.org_id`; empty `org_id` keeps legacy event shape. |
| done | Binary identity cache scope API | `BinaryIdentityCache` supports explicit org/root cache scope so the same binary path can be isolated across future nested org roots; current proxy callers still use the legacy sandbox scope. |
| done | Relay org-id boundary validation | `SupervisorSessionRegistry::open_relay_with_target` rejects invalid org ids before pending relay insertion or `RelayOpen` emission, protecting future internal callers. Validation rejects slash/space/control bytes, overlength ids, `.`/`..`, and ids starting with `-` or `.`. |
| pending | Org identity contract | Define gateway-minted immutable `org_id`; never trust labels, client input, or in-sandbox state as the org source. Propagate it through nested lifecycle, policy input, cache keys, denial/activity aggregation, and audit persistence. |
| pending | Nested org API/relay routing | Add org target to nested lifecycle and supervisor runtime selection. Existing `run_as_user` remains per-agent only. |
| pending | Nested org runtime manager | Add an outer-supervisor manager that owns per-org runtime contexts and crash cleanup. Context includes org netns, proxy, OPA, identity cache, policy-local state, provider state, mount/root, PID/proc boundary, IPC/keyring mode, cgroup, and sockets. |
| pending | Per-org user namespace or UID range contract | Use per-org user namespaces and uid/gid maps, or globally disjoint UID/GID ranges, so same numeric UID in two orgs is not the same kernel principal. |
| pending | Per-org netns allocator | Support multiple inner netns instances with unique names, veth names, CIDRs, proxy bind addresses, and cleanup. |
| pending | Per-org proxy/OPA/cache | Prefer one proxy, OPA engine, policy-local context, and `BinaryIdentityCache` per org. If shared, every route/cache/policy generation/event key must include org identity. |
| pending | Per-org DNS/metadata scope | Bind DNS and metadata emulators to org-local network scope and credentials. |
| pending | Per-org mount/root lifecycle | Create private root/work/tmp/run/dev-shm/sys/proc-sys namespaces and Landlock preparation per org. |
| pending | Per-org PID/proc boundary | Hide sibling org process metadata while preserving proxy socket-owner identity. Leading candidate: proxy identity resolver stays in the root/init PID namespace; org process trees run in child PID namespaces. |
| pending | Per-org IPC boundary | Prevent shared memory and semaphores from crossing org scope; abstract Unix sockets must be covered by per-org netns. |
| pending | Per-org keyring boundary | Disable or scope session/user keyrings per org. |
| pending | Per-org cgroup manager | Create and enforce cgroup v2 pids, CPU, memory, and IO subtrees; fail closed when delegation is unavailable. |
| pending | Org-scoped secret broker | Bind provider credentials, sandbox JWTs, metadata tokens, and relay tokens to org identity. |
| pending | Nested lifecycle API | Create/delete/restart/watch nested org sandboxes below one outer runtime. |
| pending | Linux adversarial evidence harness | Prove two orgs in one outer container cannot cross network, filesystem, proc, IPC, keyring, cgroup, secret, policy, or audit boundaries. Include active `/proc` scrape, abstract-socket enumeration, signal attempts, credential replay, and resource-pressure attempts. |
| pending | Fly feasibility proof | Verify whether Fly exposes enough namespace/cgroup capabilities for nested mode. |

## Edge-Case Validation Matrix

| Area | Covered cases | Remaining cases |
|---|---|---|
| Org id syntax | Empty id preserves legacy behavior; valid ids include `org.alpha-1`, `org_alpha_1`, and `org1`; invalid ids include slash, space, null, newline, carriage return, overlength values, `.`/`..`, leading `.`, and leading `-`. | Gateway-minted immutable org identity is still missing; request-supplied org id is carrier-only. |
| Exec org id boundary | `ExecSandboxRequest.org_id` uses the shared validator and rejects all invalid syntax before command transport. | Route exec to an `OrgRuntimeContext` after nested lifecycle exists. |
| TCP forward org id boundary | `TcpForwardInit.org_id` uses the shared validator; slash, `..`, and leading `-` are boundary-tested. | Live forward smoke must prove token replay fails across two active org runtimes. |
| Relay open org id boundary | Registry rejects invalid org ids before pending relay insertion and before `RelayOpen` emission. | Live relay smoke must prove two orgs cannot claim or observe each other's relay channels. |
| SSH session org id binding | Create-session response and persisted SSH session carry org id; forward-token validation requires matching `sandbox_id + org_id`. | Add a negative live SSH/TCP replay test once nested org runtime exists. |
| Binary identity cache | Same path in different `org_id + root_id` scopes does not collide; legacy unscoped API remains available. | Wire live proxy identity resolution to org/root scope; prove same `/usr/bin/curl` in two org roots cannot share TOFU state. |
| UID/GID policy | Same binary can be allowed for one UID/GID and denied for another; missing process identity denies scoped policy; unscoped legacy policy keeps any-UID behavior. | Live curl-through-proxy test with two OS users in one sandbox remains pending. |
| Nested org runtime | Design gaps are listed below for netns, mount/root, PID/proc, IPC/keyring, cgroup, secrets, lifecycle, and audit. | Full adversarial Linux harness remains pending before customer multi-org-in-one-outer-container claims. |

## Code Constraints Found 2026-07-06

| File/area | Constraint | Work item |
|---|---|---|
| `proto/openshell.proto` | Exec, SSH, TCP forward, and relay messages now carry optional `org_id`; sandbox lifecycle and supervisor hello remain sandbox-scoped. | Add nested lifecycle contract and gateway-minted org identity. |
| `openshell-server/src/supervisor_session.rs` | `RelayOpen` carries validated `org_id`, but there is still one supervisor session and pending relay pool per sandbox. | Route relay claim to an org runtime context once nested runtime manager exists. |
| `openshell-supervisor-process/src/netns/mod.rs` | One fixed-CIDR netns per sandbox. | Add per-org CIDR/IP allocator and cleanup. |
| `openshell-supervisor-process/src/process.rs` | One netns fd and hardcoded proxy URL `10.200.0.1`; mount namespace only hides supervisor identity socket. | Add org launch context with org proxy URL, mount/root, cgroup, and provider env. |
| `openshell-supervisor-network/src/run.rs` | One proxy, OPA, policy-local context, provider state, binary cache, and entrypoint PID. | Instantiate these per org. |
| `openshell-supervisor-network/src/identity.rs` | Binary identity TOFU cache supports `org_id + root_id + path` key scope, but current proxy callers still use the legacy sandbox scope because no org runtime context reaches the proxy yet. | Wire runtime org/root scope into proxy identity resolution once nested runtime manager exists. |
| `openshell-core/src/provider_credentials.rs` | Credential resolver generations are sandbox-scoped. | Split provider credentials by org. |
| `openshell-ocsf/src/ctx.rs` | OCSF context is one process-wide sandbox context; relay events can clone it with per-event `org_id` in `unmapped`. | Extend this pattern to policy, denial/activity aggregation, and persistent audit once org runtime context exists. |
| Docker driver | Local containers have namespace setup capabilities; Fly capability set is unknown. | Add capability probe; nested mode refuses to start when userns/netns/mount/cgroup prerequisites are missing. |

## Open Risks

| Risk | Blocking question |
|---|---|
| Cgroup delegation | Can the outer container write delegated cgroup v2 subtrees on target hosts and Fly Machines? |
| PID/proc design | Can OpenShell keep the proxy identity resolver in the root/init PID namespace while running org process trees in child PID namespaces? |
| User namespace support | Can the target runtime safely create per-org user namespaces, or must AEGIS allocate globally disjoint UID/GID ranges? |
| Capability set | Can the outer runtime safely grant namespace setup capabilities without increasing escape blast radius? |
| Cleanup | Can nested namespace, cgroup, mount, socket, and credential cleanup be made crash-safe? |
| Audit completeness | Can every policy and lifecycle event carry org identity without label spoofing or missing-context fallbacks? |
| Shared-kernel residual risk | Is this tier acceptable for customers that require VM/container-runtime tenant isolation, given nested mode still shares one kernel and outer privileged supervisor? |

## Current Recommendation

Prefer pooled hosts with separate org containers.
Revisit nested org mode only after the tracker items above have Linux evidence.
